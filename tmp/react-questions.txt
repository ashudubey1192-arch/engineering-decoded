How to use this guide
This guide collects 200 of the most frequently asked React.js interview questions, from beginner
fundamentals to senior-level topics. Every answer explains the concept in plain language, shows a
working code example, and where useful adds an interview tip on what interviewers listen for.
The content reflects modern React (React 19.x, function components and hooks, the React
Compiler, Server Components and Actions). Class components and lifecycle methods are covered
too, because they still appear in interviews and legacy codebases.
Suggested approach: read the explanation, type out the example yourself, then try to answer
the question aloud in under two minutes without looking.

Part 1: React Fundamentals
Q1. What is React?
React is an open-source JavaScript library, created by Meta (Facebook), for building user interfaces
out of reusable pieces called components. It is "declarative": you describe what the UI should look
like for a given state, and React works out how to update the browser DOM efficiently when that
state changes.
React focuses only on the view layer. Routing, data fetching and global state are handled by
separate libraries or by frameworks built on React such as Next.js or React Router.
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}
// Rendering into the page
import { createRoot } from "react-dom/client";
createRoot(document.getElementById("root")).render(<Greeting name="Asha" />);
Interview tip: In interviews, mention the three ideas that define React: components,
declarative rendering, and one-way data flow.
Q2. What are the main features of React?
• Component-based architecture: UIs are built from small, reusable, self-contained components.
• JSX: an HTML-like syntax extension that makes component markup easy to read.
• Virtual DOM and reconciliation: React compares UI trees and applies only the minimal DOM
changes needed.

Q3. What is JSX?
JSX (JavaScript XML) is a syntax extension that lets you write HTML-like markup inside JavaScript.
Browsers cannot run JSX directly; a compiler such as Babel, SWC or esbuild converts it into ordinary
function calls (React.createElement or the newer jsx() runtime).
Because JSX is JavaScript, you can embed any expression inside curly braces, and JSX itself is an
expression you can store in variables or return from functions.

Q5. What is the Virtual DOM?
The Virtual DOM is a lightweight in-memory JavaScript representation of the real DOM. When state
changes, React builds a new virtual tree, compares it with the previous one (a process called
"diffing"), and then applies only the changed parts to the real DOM.
Real DOM operations are comparatively slow because they can trigger layout and repaint. Batching
and minimizing these operations keeps updates efficient while letting developers write code as if
the whole UI re-renders every time.
function Counter() {
  const [count, setCount] = React.useState(0);
  // On each click React re-creates the virtual tree, but only the
  // text node inside <span> is actually updated in the real DOM.
  return (
    <div>
      <h3>Static heading</h3>
      <span>{count}</span>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}

Q6. What is the difference between the Real DOM and the Virtual DOM?
• The Real DOM is the browser's actual document tree; the Virtual DOM is a plain JavaScript object
copy of it kept by React.
• Updating the Real DOM directly can be slow and cause reflows; updating the Virtual DOM is
cheap because it is just object manipulation.
• The Real DOM updates immediately on every change; React batches Virtual DOM changes and
commits the minimal difference.
• Developers manipulate the Real DOM imperatively (document.querySelector...); with the Virtual
DOM you describe the UI declaratively.
// Imperative real-DOM update
document.getElementById("count").textContent = String(++count);
// Declarative React: just change state, React updates the DOM
setCount(c => c + 1);

Reconciliation is the algorithm React uses to compare the new element tree with the previous one
and decide what DOM changes are required. It relies on two heuristics that make diffing O(n)
instead of O(n^3):
• Elements of different types produce completely different trees (e.g. changing a div to a section
unmounts the old subtree).
• Keys on list children tell React which items are stable across renders.

Q8. What is React Fiber?
Fiber is the reconciliation engine introduced in React 16. It breaks rendering work into small units
("fibers") that can be paused, resumed, prioritized or discarded. This makes features like
concurrent rendering, transitions, Suspense and time-slicing possible.
Before Fiber, rendering was synchronous and could block the main thread on large trees. With
Fiber, React can interrupt low-priority work (like rendering a long filtered list) to handle urgent work
(like typing in an input).
import { useTransition, useState } from "react";
function Search({ items }) {
  const [query, setQuery] = useState("");
  const [isPending, startTransition] = useTransition();
  const [filtered, setFiltered] = useState(items);
  const onChange = e => {
    setQuery(e.target.value);                 // urgent update
    startTransition(() =>                     // interruptible update (Fiber)
      setFiltered(items.filter(i => i.includes(e.target.value))));
  };
  return <><input value={query} onChange={onChange} />{isPending && "..."}</>;
}

Q14. Why should we not update state directly?
Mutating state directly (e.g. state.count = 5 or array.push in place) does not tell React that
anything changed, so no re-render happens. It also breaks optimizations such as React.memo and
useMemo, which rely on reference comparisons to detect changes. Always call the setter with a
new value or new object/array.
const [items, setItems] = useState([]);
// Wrong - mutates the existing array, no re-render
items.push("apple");
// Right - creates a new array
setItems(prev => [...prev, "apple"]);
// Objects: copy then change
setUser(prev => ({ ...prev, age: prev.age + 1 }));

Q18. Why is using the array index as a key a bad idea?
If the list can be reordered, filtered, or have items inserted at the start, the index of each item
changes. React then associates the old component state with the wrong item. This causes bugs like
a checkbox staying checked on the wrong row or input text jumping between items. Index keys are
acceptable only for static lists that never change order.

{todos.map(t => <TodoRow key={t.id} todo={t} />)}

Q22. What are synthetic events in React?
A SyntheticEvent is React's cross-browser wrapper around the browser's native event. It exposes
the same API (target, preventDefault, stopPropagation) and behaves consistently across browsers.
Since React 17, events are attached to the root container instead of the document, and event

  return <input onChange={onChange} />;
}

Q27. What is one-way data binding in React?
React uses unidirectional data flow: data flows down from parent to child through props, and
changes flow up only through callback functions. A child cannot directly change its parent's data.
This makes it easy to trace where data comes from and why the UI changed, compared with
two-way binding frameworks.

}

  return <input value={msg} onChange={e => onChange(e.target.value)} />;
}

Q37. Why must React components be pure functions during rendering?

Q51. What are Hooks in React?
Hooks are functions, introduced in React 16.8, that let function components use state, side effects,
context, refs and other React features without writing classes. Built-in hooks include useState,
useEffect, useContext, useRef, useMemo, useCallback, useReducer, useId, useTransition,
useDeferredValue, and in React 19, use, useActionState, useFormStatus and useOptimistic. You can
also write your own custom hooks to reuse logic.
import { useState, useEffect } from "react";
function WindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);
  return <p>Width: {width}px</p>;
}
Q52. What are the Rules of Hooks?
• Only call hooks at the top level of a component or custom hook. Never call them inside loops,
conditions, nested functions or after an early return.
• Only call hooks from React function components or custom hooks, not from regular JavaScript
functions or class components.
React identifies each hook by its call order. If the order changes between renders, React assigns
state to the wrong hook. The eslint-plugin-react-hooks package enforces these rules.
// Wrong: conditional hook
function Bad({ show }) {
  if (show) { const [x, setX] = useState(0); }  // order changes!
}
// Right: hook at top level, condition inside
function Good({ show }) {
  const [x, setX] = useState(0);
  if (!show) return null;
  return <p>{x}</p>;
}
Interview tip: The new use() hook is an exception: it can be called inside conditions.

Q55. Is setState synchronous or asynchronous?
State updates are not applied immediately. Calling a setter schedules an update, and React
batches multiple updates and re-renders afterwards. Therefore reading the state variable right

updater form to work with the new value.

Q59. Explain the dependency array in useEffect.
• No array: the effect runs after every render.
• Empty array []: the effect runs only after the first render (mount) and cleans up on unmount.
• [a, b]: the effect runs after the first render and whenever a or b changes (compared with
Object.is).
Every reactive value used inside the effect (props, state, functions defined in the component)
should be listed; the exhaustive-deps lint rule helps with this. Missing dependencies cause stale
values.
useEffect(() => { console.log("every render"); });
useEffect(() => { console.log("mount only"); }, []);

Q60. What is the cleanup function in useEffect and why is it important?
The cleanup function undoes what the effect set up: removing event listeners, clearing timers,
cancelling requests or closing connections. React runs it before the effect re-runs with new
dependencies and when the component unmounts. Without cleanup you get memory leaks,
duplicate subscriptions and state updates on unmounted components.
function Timer() {
  const [sec, setSec] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setSec(s => s + 1), 1000);
    return () => clearInterval(id);   // prevents multiple intervals
  }, []);
  return <p>{sec}s</p>;
}
Q61. How do you fetch data with useEffect correctly?
Start the request in an effect, store the result in state, and handle loading and error states. Use
AbortController (or an ignore flag) in the cleanup to avoid race conditions when the dependency
changes quickly. In production apps, prefer a data library (TanStack Query, SWR) or a framework's
loaders, which add caching and deduplication.
function User({ id }) {

  const [error, setError] = useState(null);

    const controller = new AbortController();

  }, [id]);
  if (error) return <p>Error: {error}</p>;
  return user ? <h2>{user.name}</h2> : <p>Loading...</p>;
}

Q62. Why can't the useEffect callback be async?
An async function always returns a Promise, but React expects the effect to return either nothing or
a cleanup function. Returning a Promise breaks cleanup. Instead, define an async function inside
the effect and call it.
// Wrong
useEffect(async () => { const d = await load(); }, []);
// Right
useEffect(() => {
  let ignore = false;
  async function run() {
    const data = await load();
    if (!ignore) setData(data);
  }
  run();
  return () => { ignore = true; };
}, []);
Q63. What is the difference between useEffect and useLayoutEffect?
useEffect runs asynchronously after the browser has painted, so it does not block visual updates.
useLayoutEffect runs synchronously after DOM mutations but before the browser paints. Use
useLayoutEffect only when you must measure layout and update synchronously to prevent flicker,
such as positioning a tooltip. Overusing it hurts performance.
function Tooltip({ targetRect, children }) {
  const ref = useRef(null);
  const [top, setTop] = useState(0);
  useLayoutEffect(() => {
    const { height } = ref.current.getBoundingClientRect();
    setTop(targetRect.top - height);   // applied before paint: no flicker
  }, [targetRect]);
  return <div ref={ref} style={{ position: "absolute", top }}>{children}</div>;
}

Q72. What does useReducer do and when should you use it over

useReducer(reducer, initialState) manages state through a reducer function (state, action) =>

function reducer(state, action) {
  switch (action.type) {
    case "add":    return { ...state, items: [...state.items, action.item] };
    case "remove": return { ...state, items: state.items.filter(i => i.id !== action.id) };
    case "clear":  return { ...state, items: [] };

  }
}

      <p>{state.items.length} items</p>

Q79. Write a custom hook for fetching data.
A useFetch hook encapsulates loading, error and data states plus request cancellation, so
components only consume the result.
function useFetch(url) {
  const [state, setState] = useState({ data: null, loading: true, error: null });
  useEffect(() => {
    const ctrl = new AbortController();
    setState(s => ({ ...s, loading: true }));

      .then(data => setState({ data, loading: false, error: null }))

          err.message });
      });
    return () => ctrl.abort();
  }, [url]);
  return state;
}

Q80. Write a useDebounce custom hook.
Debouncing delays updating a value until the user stops changing it for a set time. It is commonly
used for search inputs to avoid calling an API on every keystroke.
function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);   // reset timer when value changes
  }, [value, delay]);
  return debounced;
}
function SearchBox() {

Q92. What is a stale closure in React hooks?
A stale closure happens when a function (inside an effect, timer or callback) captures a state or
prop value from an earlier render and keeps using that old value. It often occurs when
dependencies are missing from useEffect or useCallback. Fixes: include dependencies, use the
updater form of setState, or store the latest value in a ref.
function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      // Stale: always logs 0 and sets 1, because count is captured from first render
      // setCount(count + 1);
      setCount(c => c + 1);   // Fix: updater uses latest value
    }, 1000);
    return () => clearInterval(id);
  }, []);
  return <p>{count}</p>;
}

Q95. How do you avoid infinite loops with useEffect?
Infinite loops happen when an effect updates state that is also one of its dependencies, or when a
dependency is a new object/function on every render. Fixes: remove unnecessary dependencies by
computing values during render, use the updater form, memoize objects with useMemo, or move
object creation inside the effect.

  connect(opts);
}, [roomId]);
// Infinite loop: setting state that is a dependency

Q102. What are the lifecycle phases of a class component?
A class component goes through three phases:
• Mounting: constructor, static getDerivedStateFromProps, render, componentDidMount.
• Updating: static getDerivedStateFromProps, shouldComponentUpdate, render,
getSnapshotBeforeUpdate, componentDidUpdate.
• Unmounting: componentWillUnmount.
Additionally, error handling uses static getDerivedStateFromError and componentDidCatch.
class Lifecycle extends React.Component {
  constructor(props) { super(props); this.state = { n: 0 }; console.log("constructor"); }
  componentDidMount() { console.log("didMount"); }
  shouldComponentUpdate(nextProps, nextState) { return nextState.n !== this.state.n; }
  componentDidUpdate(prevProps, prevState) { console.log("didUpdate from", prevState.n); }
  componentWillUnmount() { console.log("willUnmount"); }
  render() { return <button onClick={() => this.setState({ n: this.state.n + 1
    })}>{this.state.n}</button>; }
}

update state, or null. It exists for rare cases where state must depend on prop changes over time.

during render, memoization, or resetting with a key.

Q112. What are error boundaries?
Error boundaries are class components that catch JavaScript errors anywhere in their child tree
during rendering, in lifecycle methods and in constructors. They display a fallback UI instead of
crashing the whole app. They implement static getDerivedStateFromError (to render fallback)
and/or componentDidCatch (to log errors). They do not catch errors in event handlers, async code
(setTimeout, promises) or server rendering.
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { logToService(error, info.componentStack); }
  render() {
    if (this.state.hasError) return this.props.fallback ?? <h3>Something went wrong.</h3>;
    return this.props.children;
  }
}

Q123. What is the Context API and when should you use it?

Q130. What is the difference between CSR, SSR, SSG and ISR?

Q137. What is useEffectEvent?

array. It separates logic that should re-trigger an effect from logic that should merely read the
latest values.
function ChatRoom({ roomId, theme }) {

    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);   // changing theme does NOT reconnect

Q142. How does React preserve and reset state based on the component

React ties state to a component's position in the render tree. If the same component type renders

position, or the key changes, the state is destroyed. This explains why conditionally swapping
identical components keeps their state.

Q143. What are the "Rules of React"?
• Components and hooks must be pure: same inputs give the same output; no side effects during
render.
• Props and state are immutable snapshots: never mutate them directly.
• Values passed to hooks and JSX must not be mutated afterward.
• React calls components and hooks: never call a component as a regular function or pass hooks
around as values.
• Follow the Rules of Hooks (top-level only, React functions only).

Q149. What is debouncing and throttling, and how do you apply them in
React?
Debouncing waits until events stop for a set time before running a function (e.g. search input).
Throttling runs a function at most once per interval (e.g. scroll or resize handlers). In React, keep
the debounced/throttled function stable across renders with useMemo or useRef, and cancel it on
unmount.

  const [results, setResults] = useState([]);
  const debouncedSearch = useMemo(
    () => debounce(async q => setResults(await api.search(q)), 300),
    []
  );
  useEffect(() => () => debouncedSearch.cancel(), [debouncedSearch]);
  return <input onChange={e => debouncedSearch(e.target.value)} />;
}

Q150. Why is defining components inside other components bad for

A component defined inside another component's body is a new function on every render. React

Q151. How do inline functions and objects in JSX affect performance?
Inline arrow functions and object literals create new references on each render. For normal DOM
elements this is cheap and fine. It only matters when passing them to memoized children or using
them as effect dependencies, where the new reference defeats memoization. Then use
useCallback/useMemo or the React Compiler.

Q152. How do you lazy load images in React?
Use the native loading="lazy" attribute so the browser defers off-screen images. For more control
(placeholders, fade-in), use the Intersection Observer API in a custom hook or component. Also
provide width and height to avoid layout shift.
<img src="/hero.jpg" alt="Hero" loading="lazy" width={800} height={400} />
function LazyImage({ src, alt }) {
  const ref = useRef(null);
  const [visible, setVisible] = useState(false);
  useEffect(() => {
    const obs = new IntersectionObserver(([e]) => { if (e.isIntersecting) { setVisible(true);
      obs.disconnect(); } });
    obs.observe(ref.current);
    return () => obs.disconnect();
  }, []);
  return <div ref={ref}>{visible ? <img src={src} alt={alt} /> : <div className="placeholder"
    />}</div>;
}

Q162. What is Redux and what are its core principles?
Redux is a predictable state container. Its principles are: a single source of truth (one store), state
is read-only (changed only by dispatching actions), and changes are made with pure reducer
functions. Redux Toolkit (RTK) is the official, recommended way to write Redux today, reducing
boilerplate.

  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment: state => { state.value += 1; },          // Immer makes this immutable
    addBy: (state, action) => { state.value += action.payload; },
  },
});
export const { increment, addBy } = counterSlice.actions;
export const store = configureStore({ reducer: { counter: counterSlice.reducer } });

Q164. What is the Redux data flow?
1) The UI dispatches an action (a plain object with a type). 2) The store calls the reducer with the
current state and the action. 3) The reducer returns new state. 4) The store notifies subscribers,
and components using useSelector re-render if their selected data changed. Middleware sits
between dispatch and the reducer to handle side effects.
// Action
{ type: "cart/addItem", payload: { id: 7, qty: 1 } }
// Reducer
function cartReducer(state = [], action) {
  if (action.type === "cart/addItem") return [...state, action.payload];
  return state;
}

Q169. What is the difference between server state and client state?

function InfiniteFeed() {

  const [page, setPage] = useState(1);

  const sentinel = useRef(null);
  useEffect(() => {

      setItems(prev => [...prev, ...data.items]);
      setHasMore(data.hasMore);

      if (entry.isIntersecting) setPage(p => p + 1);
    });
    obs.observe(sentinel.current);
    return () => obs.disconnect();
  }, [hasMore]);

}

function Countdown({ seconds = 60 }) {
  const [left, setLeft] = useState(seconds);
  const [running, setRunning] = useState(false);
  useEffect(() => {
    if (!running) return;
    const id = setInterval(() => {
      setLeft(s => {
        if (s <= 1) { setRunning(false); return 0; }
        return s - 1;
      });
    }, 1000);
    return () => clearInterval(id);
  }, [running]);
  const mm = String(Math.floor(left / 60)).padStart(2, "0");
  const ss = String(left % 60).padStart(2, "0");
  return (
    <>
      <h2>{mm}:{ss}</h2>
      <button onClick={() => setRunning(r => !r)} disabled={left === 0}>{running ? "Pause" :
        "Start"}</button>
      <button onClick={() => { setRunning(false); setLeft(seconds); }}>Reset</button>
    </>
  );
}

Q195. Implement a shopping cart with quantity and total.
Use useReducer for cart actions and derive totals during render.
function cartReducer(state, action) {
  switch (action.type) {
    case "add": {
      const exists = state.find(i => i.id === action.item.id);
      return exists
        ? state.map(i => i.id === action.item.id ? { ...i, qty: i.qty + 1 } : i)
        : [...state, { ...action.item, qty: 1 }];
    }
    case "setQty":
      return state.map(i => i.id === action.id ? { ...i, qty: action.qty } : i).filter(i =>
        i.qty > 0);
    default: return state;
  }
}
function Cart({ products }) {
  const [cart, dispatch] = useReducer(cartReducer, []);
  const total = cart.reduce((s, i) => s + i.price * i.qty, 0);
  return (
    <>
      {products.map(p => <button key={p.id} onClick={() => dispatch({ type: "add", item: p
        })}>Add {p.name}</button>)}
      {cart.map(i => (
        <div key={i.id}>
          {i.name} x
          <input type="number" min="0" value={i.qty} onChange={e => dispatch({ type: "setQty",
            id: i.id, qty: +e.target.value })} />
          = Rs. {i.price * i.qty}
        </div>
      ))}
      <h3>Total: Rs. {total}</h3>
    </>
  );
}

Q198. Build a "select all" checkbox list.
The header checkbox is derived from the items' state: checked when all are selected, and
indeterminate when only some are. The indeterminate property must be set through a ref because
it has no HTML attribute.
function SelectAll({ items }) {
  const [selected, setSelected] = useState(new Set());
  const allRef = useRef(null);
  const all = selected.size === items.length && items.length > 0;
  const some = selected.size > 0 && !all;
  useEffect(() => { allRef.current.indeterminate = some; }, [some]);
  const toggleAll = () => setSelected(all ? new Set() : new Set(items.map(i => i.id)));
  const toggleOne = id => setSelected(prev => {
    const next = new Set(prev);
    next.has(id) ? next.delete(id) : next.add(id);
    return next;                       // new Set so React sees a change
  });
  return (
    <>
      <label><input ref={allRef} type="checkbox" checked={all} onChange={toggleAll} /> Select
        all</label>
      {items.map(i => (
        <label key={i.id}>
          <input type="checkbox" checked={selected.has(i.id)} onChange={() => toggleOne(i.id)}
            /> {i.name}
        </label>
      ))}
    </>
  );
}
